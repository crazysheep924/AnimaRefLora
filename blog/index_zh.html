AnimaRefLoRA

為 Anima 擴散變換器加入參照式角色身分轉移能力，並避免參照圖成為複製捷徑。

English Website 方法 500K 結果

摘要

AnimaRefLoRA 讓原本只有文字條件的 Anima 動漫擴散變換器接收單次角色參照。偵測到的頭部裁切與完整參照，會作為乾淨的 in-context 幀放在加噪目標旁；提示詞負責控制姿勢、服裝、表情、身材與場景。核心失敗模式是「參照複製捷徑」：當參照比文字更容易利用時，模型會重現其構圖，而不是完成指定編輯。我們把逐像素內容通路定位到完整參照幀 F₁。訓練配方結合 LoKr、差異加權 flow matching、排除近重複的配對策略、標籤級 caption dropout、結構化參照 dropout，以及針對動漫的身分條件化。本頁使用更新至 500K checkpoint 的模型，以兩名 AI 生成的原創角色為對象，獨立開關外觀文字與影像參照，進行控制式質化評估。

三幀契約

頭部、完整參照與目標使用分離的旋轉位置；只有目標加噪並計算損失。

身分強化

動漫特化 CCIP 特徵轉成原型 token，並在訓練時做頭部區域表徵對齊。

反複製訓練

差異區域得到較高損失權重；配對與 dropout 防止 F₁ 成為唯一可用訊號。

技術方法

骨幹維持凍結；可訓練部分是 LoKr adapter、具 gate 的身分 token 與小型表徵投影器。

3.1

三幀訓練契約

同角色參照－目標配對排列成三個潛變量幀：F₀ 是頭部裁切、F₁ 是完整參照、F₂ 是目標。只有 F₂ 加噪與計分；F₀、F₁ 維持乾淨且 timestep 為零。

F₀頭部裁切乾淨 · 身分細節
F₁完整參照乾淨 · 服裝與輪廓
F₂目標加噪 · 在此計算損失

3.2

Rectified-flow 目標

令目標潛變量為 ztgt、高斯噪聲為 ε、噪聲量為 σ，模型迴歸線性插值路徑的 flow velocity，且只作用在目標 token。

xσ = (1 − σ) ztgt + σεv* = ε − ztgt

σ 採 logit-normal：σ = sigmoid(z)、z ~ N(0, 1)（scale 1.0），截斷於 [10⁻³, 1]，另混入 20% 的 [0.8, 1.0] 均勻高噪聲樣本——迫使模型在目標資訊所剩無幾時仍必須使用參照。訓練時不套用 timestep shift；flow shift 3.0 僅用於推論採樣。

3.3

凍結 Anima + LoKr

Anima 骨幹有 28 個 transformer block、hidden size 2048。骨幹、文字編碼器、VAE 與 modulation 全部凍結；只在 attention、MLP 上訓練 LyCORIS LoKr（dim 512、α 512、factor 4、full_matrix 分解、卷積層 dim 64／α 32；排除 modulation、norm、embedder 與 final layer）與小型身分模組。

Anima 衍生自 NVIDIA Cosmos-Predict2，繼承影片家族的跨幀 joint self-attention——因此以「額外幀」掛載參照不需要任何架構改動。但同一份繼承也自帶代價：影片先驗期待幀與幀高度相似，把參照原樣複製到目標幀，正是這個骨幹最自然的預設行為（見「避免參照複製捷徑」）。本設計直接重用這條跨幀注意力，而非另加 IP-Adapter／InstantID 式的影像編碼器 adapter——初步測試中通用影像編碼器對動漫角色身分不夠敏感。早期研究其實曾在 Anima 上直接嘗試 IP-Adapter 式 cross-attention 與 reference-KV adapter。這條路線在人工評估下始終無法明顯勝過單純的 in-context LoRA 基線，最終被放棄；本專案因此改採 in-context 路線。

3.4

不相交 RoPE 座標

若所有幀共用空間 RoPE 網格，座標對齊注意力會形成直接的複製貼上通路。因此 F₀、F₁、F₂ 除了時間索引不同，也使用不相交空間位移——與 Stand-In 的 Conditional Position Mapping（把參照 token 放進獨立座標子空間）同一直覺。實際配置：三幀時間索引 0／1／2；F₂ 置於空間原點，F₀ 沿高度軸位移一整個幀高、F₁ 沿寬度軸位移一整個幀寬（位移量＝latent 網格高／寬 × 1.0），三張幀因此落在互不重疊的座標區塊。位置配置以 JSON sidecar 隨 checkpoint 保存並在推論時驗證。

動漫特化身分條件

TOKENS

身分原型 token

768 維 CCIP（Contrastive Anime Character Image Pre-training，動漫角色對比預訓練）頭部嵌入投影為四個 token；目標 token 在 blocks 4、12、20 對其 cross-attend，scalar gate 初始化為 10−3——精神上最接近 IP-Adapter 的 decoupled cross-attention。具體接線：在這三個 block 的輸出之後，目標幀 token 各加上兩路 gated cross-attention 殘差——(a) frame adapter：query＝目標 token、key/value＝兩張參照幀的全部 token（inner dim 512、8 heads、輸出投影以 std 10⁻⁴ 初始化）；(b) 身分 token：CCIP 嵌入經 L2 正規化與 LayerNorm 後線性投影為 4×512 token，再加上可學習的 base token。兩路各有獨立 scalar gate（皆初始 10⁻³），只作用於目標幀；模組權重隨 LoKr 一併保存。消融段落提到的「frame adapter gate」即 (a) 的 gate。命名註記：此模組在程式碼與 checkpoint 中仍叫 cpm。這個縮寫是早期規劃時從 Stand-In 的 Conditional Position Mapping 借來的，後來漂移到此模組上；至於 Stand-In 原本的 CPM 概念（參照 token 使用不相交座標），則體現在 §3.4 的不相交 RoPE 配置。

CREPA

頭部區域對齊

擷取 block 8 的目標 hidden state，在頭部 ROI 池化後經兩層 MLP，以權重 0.1 的 cosine loss 對齊 CCIP。這是表徵對齊（REPA）的單圖變體；名稱沿用其跨幀延伸版 CREPA。

TEXT

Change-only caption

移除某角色至少 45% 影像共有的簽名標籤；剩餘標籤只描述姿勢、視角、服裝、身材、表情與場景變化。

避免參照複製捷徑

強參照配上弱文字，會讓「直接複製」成為最省力的降低損失方式。訓練配方保留身分，同時降低重製 F₁ 姿勢、取景與像素的報酬。

差異加權目標損失

令 d 為經平均正規化的潛變量差異 |ztgt − zref|。相同區域多半是複製監督；差異區域才包含文字指定的編輯。

w(d) = 0.2 + 0.8d,   d < 1w(d) = 1 + 0.5(d − 1),   d ≥ 1

權重圖會截斷、在頭部 ROI 保持至少 1，並重新正規化成平均 1；latent L1 也使用同一張圖。另有獨立的頭部 ROI 加權：頭部區域的 MSE 額外乘上最高 2.0 的權重，隨 σ 線性衰減、於 σ ≥ 0.6 退回 1（重噪聲下臉部本就不可回復）；兩張權重圖相乘後一併正規化。

配對

近重複排除

以多裁切 256-bit dHash 排除 Hamming 距離 25 以內的候選；找不到有效配對圖的單例「角色 × 解析度」桶則改用空白參照，避免教模型做精確的自我複製。

CAPTION

標籤級 dropout

在 50% 的訓練步中，變化標籤（signature subtraction 後剩下的 tag）各自以 0.5 機率保留，且至少留下三個。整句 caption dropout 設為零——空文字配上乾淨參照，等於直接教模型複製。

參照

結構化 dropout

25% 樣本會等機率清空 F₀、F₁ 或兩者，解耦兩條參照串流並保留無參照模式。

F₁ HINGE

非頭部反複製 margin

σ ≤ 0.8 時，若預測乾淨目標與 F₁ 在頭部以外的 cosine similarity（於 VAE latent 空間計算）超過 0.35，即啟用 hinge；接續訓練全程權重為 0.05。

L = Ldiff-MSE + 0.1 Llatent-L1 + 0.1 LCREPA + 0.05 LF1-hinge

500K Checkpoint 與訓練配方

本頁評估使用 500K checkpoint。同一套三幀架構在兩台機器上分四階段訓練：

0 → 145K · 租用 H100

在 RunPod 上從零跑驗證用訓練（約 1.9 秒/步、共約 77 小時），配方即第一版報告所述。這一階段確認了訓練設計有效、模型已堪用，因此後續不再租用 H100。

145K → 150K · 本地 RTX 5090

長程訓練改到本地閒置的 RTX 5090（約 5 秒/步）以背景工作方式進行，並加入直接 F₁ 反複製 hinge。

150K → 275K · 本地 RTX 5090

再開啟身分配件注入，訓練到早期評測使用的 275K checkpoint。

275K → 500K · 本地 RTX 5090

姿勢 × 服裝編輯

同一姿勢提示（跪姿、俯視角、舔手指的輕誘惑表情）下只切換服裝子句：中欄維持參照原服裝，右欄改為和服。兩欄共用 seed，差異可歸因於服裝文字。

組件開關對照

同一提示與 seed 下逐一關閉元件：F₀／F₁ 開關控制參照幀輸入，「CPM 關閉」把身分 token gate 歸零，「LoRA 歸零」把 LoKr 權重清空（其餘模組保留）。提示刻意不含外觀描述，身分只能來自被保留的元件。

量化解讀。關閉各元件與完整系統的輸出差異相差數個量級：LoRA 歸零＝全圖崩壞（約 100% 像素改變）、清空參照幀＝約半圖改變、CPM 關閉＝不到 9% 且不改變身分判讀；frame adapter 的 gate 在訓練中始終接近零。單幀對照中，只留 F₁ 的輸出遠比只留 F₀ 接近完整系統（差異像素 11–27% vs 25–48%）——完整參照幀承載了絕大部分身分資訊，與早期析因「F₁ 是內容通路」一致。跨 checkpoint 追蹤另顯示 CPM 的推論貢獻在訓練中期達到峰值後回落至可忽略；我們把它理解為訓練期的過渡鷹架（反複製損失壓制 F₁ 通路時的身分過渡載體），而非最終推論的必要組件。這些身分模組皆為開發過程中回應當時觀察到的失效而加入並保留（見「限制」）；「僅 LoKr＋反複製訓練配方」的最小配置是否足以達到相同結果，需由從零重訓的減法消融驗證——包括捨棄 F₀ 的 2 幀 F₁-only 變體（注意力成本約降至 4/9，且不再依賴頭部偵測）——列為後續工作。

跨底模相容性

Adapter 只在官方 Anima Base v1.0 上訓練。此處把凍結骨幹整個換成社群微調底模（WAI ANIMA v10），LoKr、身分模組與 RoPE 配置原封不動載入，以相同 500K checkpoint、相同提示與 seed 生成新的半身情境：略仰角 bust shot、單眼眨眼、手指愛心、霓虹夜街 bokeh 背景。社群近期出現以層擴充放大的 Anima 變體（在官方 2B 底模上擴充至 2.9B／3B 級）；本 adapter 是否能沿用到這些擴充架構尚未驗證。

解讀。參照身分轉移在兩個底模上皆成立——WAI 底模上略弱於官方底模，但仍明顯有效；畫風、上色與光影則跟著底模走。LoKr 與身分模組學到的是「參照條件化行為」的權重增量，換底模等於把同一份增量套在不同的影像先驗上；增量是對著官方權重學的，底模偏離原點越遠、套用誤差越大，輕微的身分弱化正符合預期。只要社群底模維持 Anima 的架構與張量形狀即可直接套用；官方與 ComfyUI 兩種權重命名格式都能直接載入。此為單場景、單 seed 的質化展示；各底模的實際適用程度仍需逐一驗證。

500K 質化發現

控制格圖用於輸入歸因而非挑選最好看的結果；成對格共用噪聲，因此變化可對應到外觀詞、影像參照或兩者交互作用。

外觀文字提供語意結構。

文字能加入兔耳、叉角等寫得出來的特徵，但無法還原未寫出的細部裝飾。

影像提供個體身分。

參照會帶入色彩配置、臉型與輪廓；臉部在畫面中佔比極小時，身分仍會弱化。

兩者互補。

有外觀＋有參照通常最穩定：文字釐清顯著外觀特徵、避免歧義，影像則補上 tag 沒寫到的細節。

不需複製構圖。

無論是咖啡館坐姿、近景表情還是成對身材編輯，角色都能正常生成，而不是照搬去背立繪來源圖的構圖。

互動構圖可由文字指定。

冬夜市集的 POV 牽手回眸與海濱餵食都能成立——參照是正面立繪，模型仍能生成朝向鏡頭的互動姿勢與表情。

身材可由文字控制。

兩角色的 petite／curvy 配對皆出現清楚胸腰臀變化。

解讀界線。每列只有一個 seed；這些結果展示支援行為與失敗模式，不估計成功率。

早期研究證據

早期研究中促成後續訓練方向的關鍵量測結論。

整句 caption dropout

含整句 dropout 的配方約 10K 步就開始複製，不含者約 25K 步才出現；兩組另有 reference dropout 設定差異，因此並非單變量消融。

F₁ 是內容通路

16 路析因與分區 NCC 將近逐字的下半身像素定位到完整參照 F₁。

近重複是次要因素

寬鬆門檻近重複只佔抽樣同角色配對約 0.4%，不足以解釋早期 41% 人工複製率。

歷史評測觀察可下的結論
80K 的 22 參照基準9/22 逐字複製（41%）早期配方確實有嚴重的捷徑問題。
105K：diff 加權＋較低頭部區域損失權重的 resume1/22 複製（4.5%）與更快離開複製期一致；非單變量因果結果。
從零驗證 run（原定 150K，止於 145K）複製期約 95K 達峰、100K 後崩落訓練動態本身也能降低複製，此處缺乏干預控制。

ComfyUI 部署

模型以獨立 ComfyUI 插件 ComfyUI-AnimaRefLora 發佈：載入一張參照圖、輸入提示詞，就能得到與本報告評測管線一致的結果。

為什麼不用 ComfyUI 內建採樣器

ComfyUI 內建的 Anima 採樣路徑只支援到 max_h = 120 的 RoPE 位置上限。我們的模型刻意把兩張參照幀與目標幀放在分離的位置座標上（§3.4），需要的座標範圍遠超過 120；硬塞回 120 會讓各幀座標重疊，等於重新打開訓練時特地關掉的「複製貼上」通路。因此插件完全跳過 KSampler，直接用本專案自己的推論迴圈採樣，並使用存放在每個 checkpoint 旁的 RoPE 配置。

LOADER

Anima RefLora Loader

一次載入全部：Anima 底模、訓練好的 LoKr 權重、身分模組、RoPE 配置與 VAE。可選節點可再疊一個一般的 Anima 風格 LoRA。

ENCODE

Anima Ref Encode

接收參照圖，偵測頭部，把頭部裁切與整張圖轉成兩張參照幀，並算出 CCIP 身分向量。輸出尺寸在此以 64 像素為步進設定（1024×1024、1024×576、1152×768…）；參照圖採 letterbox 而非裁切，避免裁掉角色邊緣。

SAMPLER

Anima RefLora Sampler

用與本頁評測管線相同的採樣迴圈生成圖片——三幀排列與引導方式都與訓練一致。不加額外風格 LoRA 時，輸出與本頁評測管線逐位元相同。

節點流程就是 Load Image → Ref Encode → Sampler，Loader 負責供應模型。建置腳本會把插件打包成約 15 MB 的可攜資料夾，內含推論所需的最小程式碼；模型檔放在 ComfyUI 慣用的 models/ 目錄。推論已在 32 GB 的 RTX 5090 上以 1024×1024 測試通過，VRAM 需求隨輸出解析度成長。插件、程式碼與訓練權重皆已公開發佈；權重透過 HuggingFace 散佈。

限制

本評估只有兩名角色、四種控制編輯、兩種原服裝姿勢與每列一個 seed；不是身分 benchmark 或使用者研究。500K 是同時更動資料與數個旗標的 continuation，不能把改善歸因於單一組件。參照圖為 AI 生成的原創設計而非自然場景圖；生成參照本身的畫風也可能影響輸出風格。後續應加入多 seed、盲測身分判斷、CCIP 距離、prompt adherence、複製偵測與外部 adapter 基線。

另需說明，本訓練配方是專案迭代過程中逐步累積而成，並非經過系統性設計的最小組合。開發以「最快取得可用模型」為優先，因此採取疊加式改進——在既有配方上加入新機制後繼續訓練——而非為每項機制進行獨立的控制實驗。各項機制皆為回應開發當下觀察到的特定失效模式而引入，於問題緩解後保留至今；完整堆疊尚未進行由上而下的減法消融。因此部分組件之間可能存在功能重疊或冗餘，更精簡的配方或許足以達到相同效果，所需引入的專有機制與術語亦可隨之減少。本頁如實記錄實際訓練所用的完整系統，而非可運作的最小配方。訓練資料取自 Danbooru；程式碼、ComfyUI 插件與訓練權重皆公開發佈。
